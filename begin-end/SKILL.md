# 开头结尾优化 (begin-end) · 多领域版

## 概述
专门优化文章的**开头**与**结尾**。不同领域的开头使命与结尾落点完全不同：

| 领域 | 开头使命 | 结尾落点 |
|---|---|---|
| 母婴 | 秒认亲（你懂我） | 接住她（有力量 / 被治愈） |
| 娱乐 | 上猛料（信息差 / 情绪冲击） | 想转发 / 想吐槽（社交货币） |
| 情感 | 共情（这说的不就是我） | 被治愈 / 被理解（想转发给某人） |
| 人生哲学励志 | 共鸣 + 认知差 | 余味 / 行动（想收藏） |
| 女性觉醒 | 刺痛 + 颠覆认知 | 点燃（我看见了，不再闭眼） |
| 财经 | 确定性（这不就是我） | 行动感 / 方法清单（我学到了） |

打法细节（开头模型 / 结尾模型 / 公式 / 范例 / 雷区 / 自检 / IP 映射）全部在各领域的 `references/<domain>.md`，本文件只做流程编排与领域路由。

**专攻边界**：本技能只优化文章的「开头」与「结尾」两段——不重写中段正文、不做整篇改写、不写标题（标题有独立 title 技能）、不生成配图。产出的是可直接套用的钩子 / 模板候选，不是替你发稿。

## 何时使用
用户给出文章（粘贴文本 / 文件路径 / 选题），并表达以下任一意图：
- 优化 / 改写 / 打磨文章的开头、结尾，或两者。
- 要一个"爆款开头""共鸣开头""治愈结尾""金句结尾""点燃式结尾""方法清单结尾"。
- 给的草稿开头太文艺 / 不痛不痒 / 结尾像教导主任，需按某领域逻辑重做。

## 快速上手（示例）

用户：「这篇娱乐稿开头太温了，帮我爆一点」+ 粘贴文章。

1. **路由**：检测到「明星 / 塌房」等关键词 → 读 `references/entertainment.md`。
2. **读手册**：取「开头模型」列表，挑 2 个最贴合主调的钩子（如 模型二 反转打脸 / 模型三 悬念钩子）。
3. **产出**：给「原文开头」+「优化版 A（反转打脸，适用…）」+「优化版 B（悬念钩子，适用…）」+ 一句推荐组合。
4. **结尾若也要求**：同法取 `entertainment.md` 的结尾模型。

母婴文同理，但落款强制「福宝妈妈育儿笔记」、宝宝名用「福宝」且正文频率压到最低（用「娃 / 宝宝 / 她」代替）。

## 输入与范围判定
1. 接收内容：优先接受整篇草稿（最稳）；也可只给开头段 / 结尾段 / 纯选题。
2. 判定范围：用户说"开头"→ 只动开头；说"结尾"→ 只动结尾；没说 → 默认两者都给优化建议。
3. 若只给选题（无正文）：按选题主调，从对应手册直接产出 2 个开头钩子候选 + 2 个结尾模板候选供选。

## 领域识别（路由，必须先做）
1. **显式声明优先**：若用户在请求中点名领域（如"这是篇娱乐稿""母婴文优化结尾"），直接用，不追问。
2. **关键词推断**：否则从内容关键词推断（下表）。推断有把握时直接路由，不追问。
3. **无法判断则追问**：若关键词冲突 / 信息不足，**用 AskUserQuestion 让用户从 6 大领域中选择**，不要猜。
4. **子类处理**：女性觉醒 / 财经含子类。先定主域，再按文章内容挑选合适子类模型（通常无需单独追问）；仅当文章明显跨子类、且模型选择会大幅不同时，才追问子类。

**关键词速查（辅助推断，非硬规则）**
- 母婴：娃 / 宝宝 / 育儿 / 妈妈 / 哄睡 / 辅食 / 早教 / 纸尿裤 / 产后
- 娱乐：明星 / 影视 / 综艺 / 红毯 / 八卦 / 剧 / 票房 / 塌房 / 爱豆
- 情感：爱情 / 失恋 / 婚姻 / 分手 / 孤独 / 朋友 / 治愈 / 释怀 / 异地
- 人生哲学励志：成长 / 认知 / 内耗 / 自律 / 能量 / 人生 / 通透 / 自我提升
- 女性觉醒：女性 / 独立 / 规训 / 既要又要 / 丧偶式 / 婆媳 / 职场女性 / 重男轻女 / 枷锁 / 醒来
- 财经：理财 / 存款 / 投资 / 房价 / 公司 / 财报 / 消费 / 通胀 / 攒钱 / 负债 / ROI

> 易混提示：人生哲学励志与女性觉醒都可能出现"觉醒"字眼——人生哲学偏**性别中立的认知 / 能量 / 内耗**；女性觉醒带**性别视角与"枷锁 / 醒来 / 力量"**语义，且常落在婚恋 / 原生家庭 / 职场场景。

## 工作流
1. **读取对应手册**：先读路由表指向的 `references/<domain>.md`（母婴用 `muying.md`），作为该领域模板 / 示例 / 避坑 / 自检 / IP 映射的唯一依据。
2. **判定文章主调 / 子类**：从主题 / 情绪落点归类，据此选开头钩子与结尾模板；多给 **2 个候选**并标注各自适用场景，让用户挑。
3. **起草优化版**：
   - 开头按所选钩子重写，首句即命中该领域核心使命（认亲 / 猛料 / 共情 / 共鸣 / 刺痛 / 确定性）。
   - 结尾按「收束 → 情绪 / 价值转化 → 落点（送别 / 转发 / 行动 / 点燃 / 落地）」三步法；避免结尾新抛焦虑 / 大观点，但母婴域可叠加软引导（收藏 / 评论 / 关注，须包装成对读者有用的提醒，详见 `muying.md` §2.4）。
   - 优先给 2 个候选（不同钩子 / 不同模板），并标注各自适用场景。
4. **套用 IP 身份映射**（领域相关）：
   - 母婴 → **强制福宝妈妈**（署名「福宝妈妈」、落款「福宝妈妈育儿笔记」、自称「小琳 / 福宝妈妈」、宝宝名「福宝」且正文频率压最低，用「娃 / 宝宝 / 她」代替）。不在正文保留任何提取人设的源品牌名。
   - 其他域 → 沿用文章自身人设 / 来源写作人设（可参考 renshe-writer / meta-persona）；未指定则保留原文署名，**不套用福宝妈妈**。
5. **跑自检清单**（对应手册的开头 / 结尾自检，若手册未单列则按该域雷区逐条过）：不过则回改。
6. **真实事件纪律**（所有域通用）：若涉及真实事件 / 研究 / 数据，按真实写，不擅自加"假设 / 虚构 / 推演"标注；来源不确定先 WebSearch 核实，不为钩子效果编造事实。

## 输出规范
- 用对比呈现：先给「原文（或原思路）」，再给「优化版 ×N」。
- 每个优化版附 **1 行选用理由**（为什么这个钩子 / 模板适合这篇文章的主调）。
- 末尾给一句「推荐组合」建议（如"娱乐文开头用模型二反转打脸 + 结尾用模型四互动引战，传播性最强"）。
- 落款：母婴统一「——福宝妈妈育儿笔记」（仅正式落款时加）；其他域按文章自身人设落款或省略。

## 目录设计（输出约定）

> 本 skill 为 prompt 驱动的「开头 / 结尾」优化，**默认不产生文件产物**——产出的是可直接套用的钩子 / 模板候选（对比呈现于对话中）。因此不占用统一会话目录（§1.1 仅约束有文件产物的 skill）。
> 若用户要求把优化结果落盘保存，应遵循规范写入统一会话目录 `~/WorkBuddy/begin-end_{YYYYMMDD-HHMM}/`，并以 `{序号}_{阶段功能名称}_{主题}` 命名（如 `0_begin_end_<主题>.md`）。本 skill 自身不持有 stage 登记（除非被要求落盘）。

- **无默认文件产物** → 不登记输出件登记表。
- **源输入**：用户粘贴的文本 / 文件路径 / 选题，属内存态或用户源文件，不绑定任何外部固定路径；源文件只读、不回写。
