# AGENTS.md · 知识库操作规则

> AI 在本库执行任何操作前先读本文件。最近生成：{{date}}。

## 1. 动作许可表

{{rules_table}}

安全底线（任何档位不可放开）：
- 改源资料、删除文件：恒为 L2（先方案 + 确认）。
- 写 / 改本文件与 README：L2。
- **删除一律先入回收站/归档，不物理删除**——这条是**约定，无脚本强制**（本 skill 不代你做删除）。

## 2. 源资料保护

1. 源目录所有文件只读：不删、不改、不重命名；唯一例外是用户明确授权且逐文件确认的"未归桶资料归位"。
2. 不复制原文正文、图片、PDF、视频、安装包；笔记用相对路径引用。
3. 不用摘要替换原文；原始资料默认保护正文。
4. 同名文件不覆盖、不自动合并：遇同名先报告差异，由用户决定保留/改名/人工合并。
5. 创建或移动前检查目标路径。

> 本节第 1、4 条由 `scripts/verify.py` 的 **C14 源目录只读**机器把关：Step 5 建 `_meta/source_snapshot.json`
> 基线（资料文档逐篇 sha256，媒体只计数量）后，每次 verify 都比对现状——**被改 / 被删 → FAIL**；
> 新补进来的资料 → **WARN**（提示重建基线并走 intake，不当事故）；只改 mtime、内容没变 → **PASS**。
> 基线**只能显式** `verify --snapshot-source` 建，脚本永不自动重建；verify 也**不写源资料**。

## 3. 格式规整边界

可直接处理（不改变含义）：多余空行/纯空格行、行尾空格与不可见字符、导入造成的重复首标题、空标题、明显断裂的序号/项目符号、列表间多余空行。
不可直接处理：改写或润色正文、删除可能有意义的段落、调整观点顺序、改变标题层级含义、用摘要替换原文。
分不清是格式修复还是内容修改时，一律先询问。

## 4. 多维标签、结论与来源

1. 笔记按 6 维度（`domains/forms/tools/types/projects/sources`）打多值标签；标签值取受控词表、同义词先归一；新增长尾标签须人工确认，不自动生效。
2. 任一核心维度靠推断、信心不足时，笔记进 `99_收件箱`，不直接入 `notes/`。
3. 每条结论挂 `sources`（相对路径）；三段写死：`evidence.quote`=资料原话（逐字、validate 严格子串）、各类型主字段=归纳结论、`inference`=AI 推断，三者不可混；数字/日期/命令/代码逐字保留、不归一。
4. 数字须能在原文定位，否则标"未核实"；资料不足时说明缺什么，不补写不存在的事实。
5. 检索（`search_index.py`）为只读；项目拉取以 `projects/<项目>/recipe.yaml` 为唯一入口，不临时翻文件、不凭记忆给结果。
6. 深抽 units 遵守 `references/08` 第 3 节 10 条硬约束：只依原文、无来源写 null、不补外部知识、不确定标 low、冲突不合并（建 conflict 保留双源）、一块多结论按语义拆篇、禁用签名 URL 与导出占位作 evidence（预签名链接 24 小时失效，不可回放）。
7. 单元合并保留全部 evidence（转数组）；同 doc concept/relation 合并、跨 doc claim 不自动合并、跨 chunk procedure 按 steps.order 拼接。

## 5. 高风险操作与备份

批量移动/重命名、删除/覆盖、目录重构、大规模正文修改、导入大量唯一原件之前：
- 先出方案等待确认；
- 生成 `操作前清单_<时间戳>.md`（篇名/原路径/目标路径）；
- 完成后核对文件数量并随机回读，再汇报。

## 9. 自检与失败处理

1. 每批生成后回读产物，运行 `verify.py --kb <KB> --config <工作目录>/config.json` 与（开了 units 时）`validate_extraction.py`；任一 error 未清零不放行——**两个脚本都有真退出码**：verify 有 fail 即 exit 1；validate 在 `units.jsonl` 缺失或 0 条时 exit 1 并拒绝打印「通过」（没开 units 就别跑它，它不是非 units 路径的放行依据）。文件存在不等于正确。
2. 逐篇 `sources` 非空且可达 = **C5，缺即 FAIL**；`confidence` 为 low / 缺失 = **C15，只 WARN 并提示进 `99_收件箱`**——是否挪走仍是人的决定，脚本不搬文件。
3. 高价值块处理率 100%；inbox 占本批高价值块 >20%（小批次 <10 块人工判断）不放行；抽检条目通过率 <95% 回滚到收件箱。**这两条是人工闸，没有脚本把关**——自己算，别等工具提醒。
4. 失败先读报错根因，记录到 `_meta/问题资产库.md`（现象/根因/解法/预防），再决定重试或换通道；禁止盲目重试、禁止以相同方式重复失败操作。
