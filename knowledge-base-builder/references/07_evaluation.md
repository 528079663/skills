## 1. 评估总览与门禁

| 质量线 | 数据集 | 核心指标 | 默认门禁（可调） |
|---|---|---|---|
| 入库·分类 | 多标签分类黄金集 | 每维度 macro-F1、micro-F1、每维度召回 | 每维度 macro-F1 ≥ **0.85**；核心维度 domains/tools/types ≥ **0.90** |
| 使用·检索 | 黄金查询集（含项目级） | Recall@k、MRR、nDCG@k、延迟、项目级召回 | 项目级 Recall@k ≥ **0.90**；MRR ≥ **0.80**；P95 延迟 < **300ms** |

门禁规则：
- 批量打标前：分类指标达标，否则回到打标规则/词表修正。
- 交付前：检索指标达标；任一项目配方拉取漏召（<0.9）需修正条件或说明 gold 边界。
- 指标与样本量一并报告；样本过少（如某维度 gold < 20 篇）标注"低置信，仅供参考"。

## 2. 多标签分类黄金集

结构（每篇文档标注**每个维度**的期望标签值）：

```json
[
  {
    "path": "原始文档_04_.../用Codex自动剪AI口播视频.md",
    "domains": ["AI", "编程"],
    "forms": ["自媒体", "视频"],
    "tools": ["Codex", "剪辑"],
    "types": ["教程"],
    "projects": ["AI自媒体", "Codex剪辑"],
    "sources": ["妙记"]
  }
]
```

要点：
- 旧的 740 行单标签 CSV **不能直接当多维真值**：它只覆盖单一主题列，需升级（见第 6 节）。
- 每个维度独立评估；某维度 gold 为空表示该维度不参与本次评估。
- 预测结果由 `tag_documents.py` 产出，与 gold 逐维度比对。

## 3. 分类指标定义

对每个维度 `dim`、每个标签值 `t`，按文档统计：
- TP：gold 含 t 且预测含 t；
- FP：gold 不含 t 但预测含 t；
- FN：gold 含 t 但预测不含 t。

由此计算：
- precision(t) = TP / (TP + FP)
- recall(t) = TP / (TP + FN)
- F1(t) = 2·P·R / (P + R)

汇总到维度：
- **micro-F1**：把该维度所有标签的 TP/FP/FN 分别求和后再算 P/R/F1（受高频标签影响大）。
- **macro-F1**：该维度各标签 F1 的算术平均（每个标签等权，能暴露长尾标签问题）。
- **每维度召回**：该维度 micro-recall = ΣTP / (ΣTP + ΣFN)。
- **精确率**：micro-precision = ΣTP / (ΣTP + ΣFP)。

混淆/误分配：
- 单值维度（`sources`）：直接出混淆矩阵（真值标签 → 预测标签计数）。
- 多值维度：输出 top "误分配对"（gold=t1 但被预测成 t2 的文档数），定位易混标签（如"教程 vs SOP"）。

## 4. 黄金查询集（含项目级）

每条用例：输入（关键词/维度条件/配方）+ 期望相关文档集合 gold：

```json
[
  {
    "id": "q_codex_edit",
    "input_kind": "query",
    "query": "Codex 剪辑教程",
    "dims": {},
    "gold": [".../用Codex自动剪AI口播视频.md"]
  },
  {
    "id": "proj_ai_media",
    "input_kind": "recipe",
    "recipe": "projects/AI自媒体/recipe.yaml",
    "gold": ["...A", "...B", "...C"]
  }
]
```

- 普通查询：检验关键词 + 维度组合的检索质量。
- **项目级查询**：直接跑配方，gold = 该项目应包含的文档集合，检验"一键拉取能不能拉全、排得靠前"。

## 5. 检索指标定义

对一条用例，取排序结果 `R = [r1, r2, …, rk]`，相关集合 `gold`，相关性二值（在 gold 中=1）：

- **Recall@k** = |R[:k] ∩ gold| / |gold|
- **Precision@k** = |R[:k] ∩ gold| / k
- **MRR**：第一个相关结果排名 `rr` 的倒数 `1/rr`（无相关则 0），多查询取平均。
- **nDCG@k**：
  - DCG@k = Σ_{i=1..k} rel_i / log2(i+1)
  - nDCG = DCG / IDCG（理想排序的 DCG）；多查询平均。
- **项目级召回率**：配方拉取的 Recall@k（k=配方 limit）。
- **延迟**：单次查询墙钟耗时（ms），报告均值与 P95。

说明：
- gold 覆盖的是"已知应命中"集合；不在 gold 但被召回的结果计入 precision 惩罚，故 gold 需尽量完整，否则指标失真。
- 二值相关足够时不引入分级相关；若要区分"强相关/弱相关"，可在 gold 用 0/1/2 分级，nDCG 相应加权。

## 6. 黄金集的构建与维护

多标签分类黄金集：
1. 从源 `主题分类清单.csv`（740 行）取文档全集与单主题，作为抽样框与**弱标签**参考。
2. 首版抽样 **50–100 篇**（覆盖各主题/各来源），由 AI 按六维度预标注、**人工逐篇复核**，形成可信 gold。
3. 打标规则每次大改后，用同一 gold 回归测试；误判样本回填进 gold 持续扩充。

黄金查询集：
1. 从真实项目（AI自媒体、Codex剪辑、B站好物等）提炼 10–20 条高频查询/配方。
2. gold 集合由人工确认（宁少而准）；项目配方的 gold 可用"人工核对该项目应含文档"得到。
3. 新增项目配方时同步补项目级用例。

## 7. 评估流程

1. 生成预测：`tag_documents.py` 对 gold 文档跑打标 → 预测标签。
2. 建索引：`search_index.py build`。
3. 跑评估：
   ```
   python scripts/evaluate.py classify --gold <gold.json> --pred <pred.json>
   python scripts/evaluate.py retrieval --kb <kb> --queries <queries.json>
   ```
4. 输出：机器可读 JSON（每维度 P/R/F1、每查询 Recall/MRR/nDCG、延迟）+ 人读汇总（达标/未达标、最差维度与查询、改进建议）。
5. 未达标：记录到问题资产库，修正词表/规则/排序后重跑；**禁止在指标未达标时批量或宣布完成**。
