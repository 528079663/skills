# 05 · 辅助层：多属性标签模型

> **注意**：本篇描述的六维标签（domains/forms/tools/types/projects/sources）在新模型中**降为辅助层**，用于跨工作流检索，**不决定物理目录**。物理目录由 flow/stage/substage 决定（见 `09_workflow_model.md`）。
>
> 本篇是对 `02_archetypes.md`、`03_rules_engine.md`、`04_pipeline.md` 的补充：当文档具有多重属性、且需要跨工作流聚合时，以本篇为准。
> 受控词表：`assets/taxonomy/taxonomy.json`（辅助维度、核心标签、同义词、项目配方种子）。

## 1. 核心转变

| 旧模型 | 新模型 |
|---|---|
| 一篇文档归入一个"桶/主题文件夹" | 文档**物理只存一份**，携带**多维度、多值标签** |
| 标签平铺，领域/工具/类型混在一起 | 标签分 **6 个维度**，每维度独立取值 |
| 知识模块 = 文件夹 | 知识模块 = **标签组合视图**（不落物理目录） |
| 检索靠"进对文件夹" | 检索靠"维度过滤 + 全文/向量索引" |

目标：同一篇《用 Codex 自动剪 AI 口播视频》在 AI、自媒体、Codex 剪辑等**多个模块/项目都能被召回**，且物理上只有一份。

---

## 2. 六维度定义

| 维度（键名） | 含义 | 多值 | 示例值 |
|---|---|---|---|
| `domains` 领域 | 属于什么知识领域 | 是 | AI、编程、商业、营销、设计 |
| `forms` 形态 | 以什么形式呈现 | 是 | 自媒体、视频、文章、直播、播客、提示词 |
| `tools` 工具/技术 | 涉及什么工具或技术 | 是 | Codex、Claude、剪辑、即梦、微信小程序 |
| `types` 类型 | 内容的性质 | 是 | 教程、案例、复盘、素材、观点、SOP、问答 |
| `projects` 项目 | 属于哪个/哪些项目 | 是 | AI自媒体、B站好物、Codex剪辑 |
| `sources` 来源 | 从哪来 | 否（单值） | 妙记、PDF、网页剪藏、原创 |

规则：
- 除 `sources` 单值外，其余维度**均可多选**；拿不准就多选 + 低信心，不要强行二选一。
- 维度集合固定为 6 个；新增维度须人工确认，不自动扩。
- 每维度核心标签控制在 **10–30 个**；不足则补、过多则归并。

## 3. 文档 frontmatter schema

提炼笔记（知识层文件）统一头部：

```yaml
---
title: 用Codex自动剪AI口播视频
# 主轴（决定物理位置，见 09_workflow_model.md）
flow: Codex剪辑
stage: 2_做视频
substage: 子技巧
# 辅助层（六维标签，跨工作流检索）
domains: [AI, 编程]
forms: [自媒体, 视频]
tools: [Codex, 剪辑]
types: [教程]
projects: [AI自媒体, Codex剪辑]
sources: ["<源文件相对路径>"]
source_kind: 妙记
confidence: 0.92
classified_by: 规则+AI复核
created: 2026-09-30
updated: 2026-09-30
stale: false
---
```

要求：
- **主轴三字段（flow/stage/substage）必填**，决定物理目录；详见 `09_workflow_model.md` 第 4 节。
- `sources` 必填、路径真实可达（verify 校验）。
- `confidence` 记录整体打标信心；任一核心辅助维度靠推断且 < 阈值，整篇进 `99_收件箱` 待确认。
- `classified_by` 标注来源：`规则` / `AI` / `规则+AI复核` / `人工`。

## 4. 标签规范

1. **多值**：每维度可挂多个值；同维度多值在检索中按 **OR** 处理（见 `06`）。
2. **同义词合并**：`AI/人工智能`、`Claude/claude code` 等统一到一个规范值，映射表在 `taxonomy.json -> synonyms`。命中同义词先归一，再写入。
3. **层级 ≤ 2 层**：形如 `AI > 提示词`；不建第三层，过深则拍平或拆维度。
4. **核心 vs 长尾**：
   - 核心标签（每维度 10–30 个）：**人工定义/确认**；
   - 长尾标签：AI 建议进入候选区，**人工确认后才生效**，不自动写入受控词表。
5. **归档而非删除**：连续约 180 天 0 引用的标签转入归档；需要时可恢复。
6. **大小写/中英文**：写入统一规范写法（工具名保留官方大小写，如 `Codex`、`Claude`）。

## 5. 物理存储与逻辑组织分离

> **目标物理结构以 `04_pipeline.md` 第 1 节为准**（工作流 → 环节 → 子分组）。本篇只定义辅助层的六维标签模型，不定义目录。

原则：
- 一篇原子笔记物理只存一份，位于 `工作流/<flow>/<n>_<stage>/`；
- **"它属于哪些模块/项目"由六维标签和 projects 维度表达**，不建实体文件夹；
- 模块视图（如"AI 领域""自媒体形态"）由检索动态生成，可在 `00_导航` 保存为命名视图；
- `projects/<项目>/` 只放 `recipe.yaml` 与该项目的产出物（跨工作流一键拉取的辅助入口）。

## 6. 桶与"形态"的新定位

- **桶（源目录的物理归档，如"01 AI编程"）**：保留为**源资料的物理主归属**，便于回溯；知识库检索**不依赖桶**。
- **形态（学习/创作/项目，见 `02_archetypes`）**：不再决定物理目录，改为决定三件事：
  1. 默认生成哪些**项目配方/命名视图**（创作型→自媒体相关配方；项目型→具体项目配方；学习型→学习路径视图）；
  2. 默认**笔记深度档**（学习→card、创作→topic、项目→deep）；
  3. 维度/标签的关注权重（如创作型更重 forms/projects）。

形态比例算法（`02` 第 5 节）保留，用于选默认配方与笔记档；物理骨架统一走本篇第 5 节。

## 7. 打标流程（规则 + AI + 人工）

对应脚本 `scripts/tag_documents.py`（确定性部分）+ 执行 AI（语义部分）：

1. **规则初筛**：按路径、文件名、源 CSV 已知标签、同义词表，机械命中一批维度标签；命中即高信心。
2. **AI 语义打标**：对规则未覆盖/跨维度文档，读标题 + 开头 N 字（默认 500），给出每维度建议值 + 信心度。
3. **受控校验**：建议值不在受控词表 → 标记为候选长尾，不自动生效。
4. **信心度处置**：
   - 高（≥0.85）：写入 `工作流/<flow>/<n>_<stage>/`；
   - 中（0.6–0.85）：写入但标记待抽检；
   - 低（<0.6）或核心维度缺失：进 `99_收件箱`，人工确认。
5. **人工确认**：核心标签与项目归属以人工确认为准；`projects` 维度尤其需要用户确认。
6. **回测通过才批量**：用多标签黄金集评估（见 `07`），每维度 macro-F1 达标后再批量打标。
