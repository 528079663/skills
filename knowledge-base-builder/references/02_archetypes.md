## 5. 混合形态：比例算法

问卷 Q1 让用户对目标（a 学习 / b 创作 / c 项目 / d 沉淀提示词 / e 教别人）按重要性排序或多选。`render_config.py` 按下列规则算比例：

### 规则 5.1 · 显式排序 → 权重

用户给出排序（如 b > a > c），用位次权重：

```
weight_i = (N - rank_i) / Σ(N - rank_j)      # N = 已排序目标数，rank 从 0 起
```

例：b,a,c 三项排序 → b=(3-1? 以 rank 0,1,2 计)：
- rank0 → (3-0)/6 = 0.50
- rank1 → (3-1)/6 = 0.33
- rank2 → (3-2)/6 = 0.17
即 b:a:c = 50:33:17。

### 规则 5.2 · 仅多选无排序 → 均分

选中项均分权重；未选项为 0。

### 规则 5.3 · 目标项归并到三形态

- a 学习 → 形态 A
- b 创作 → 形态 B
- c 项目 → 形态 C
- d 沉淀提示词/SOP → 计入 B（提示词库）与 C（跨项目方法），各半
- e 教别人 → 计入 A（学习路径/教程），并在规则中保留"对外模板/脱敏"要求（【Blake】对外分享）

### 规则 5.4 · 主导与混合判定

- 某形态权重 ≥ 0.6 → 单一形态，用其骨架。
- 否则 → 混合形态，以权重最高者为主干，按第 6 节并入其他形态目录。
- 三形态权重均 < 0.4 且接近（极差 < 0.15）→ 默认以 B 为主干（素材库对其他形态兼容性最好），并在方案中注明。

### 规则 5.5 · 兜底

Q1 缺失或全 null：默认 B（创作型），权重 1.0，并在方案显著位置标注"目标未明确，暂按创作型生成，可随时调整"。

## 6. 混合形态：目录合并规则

以主干骨架为基础，按次形态权重并入目录：

| 次形态 | 并入的目录（加到主干） | 并入条件 |
|---|---|---|
| A 学习 | `02_卡片/`、`00_导航/学习路径.md` | A 权重 ≥ 0.2 |
| B 创作 | `02_提示词库/`、`05_选题池/` | B 权重 ≥ 0.2 |
| C 项目 | `projects/`（仅建用户当前真实推进的项目） | C 权重 ≥ 0.2 且用户能说出项目名 |

合并约束：

1. **目录不重复创建**：主干已有同义目录则合并（如主干 B 的 `02_提示词库` 与 C 的 `01_跨项目方法/提示词` 合并为一处，以主干命名为准）。
2. **编号重排**：合并后一级目录按实际顺序重编号，编号仅为排序，不表达层级含义。
3. **空目录不落地**：并入目录在当前没有真实资料/项目承接时，只在方案中列出为"预留"，不实际创建（【Blake】"不要创建当前没有真实用途的分类"）。
4. 混合后的完整目录树必须在方案中逐行展示，由用户确认。

```markdown

- 资料概况：md N 篇 / 妙记 N 条 / 孤儿资料 N 项（来自 scan 结果）
- 协作偏好：…（规则档位）

## 2. 目录骨架
（完整目录树，标注哪些是"预留、暂不创建"）

## 3. 规则表（AGENTS 摘要）
| 动作 | 处置 L0/L1/L2 |

## 4. 笔记模板
（所选档模板的字段清单）

## 5. 特殊资料处理
- 未归桶资料：…
- 无精华逐字稿：…
- 孤儿 PDF / 卡片型 PDF：…

## 6. 样板笔记（5 篇）的原文选择
| # | 原文 | 主题 | 选它的理由 |

## 7. 替你默认的事项（可改）
- …

确认后我将按此生成；现在不写任何文件。
```
