## 1. 三篇文档各自在解决什么

### 【Blake】解决"人与 AI 的协作契约"

Blake 是非技术背景（电商 12 年），他的文档本质是一套**可照抄的提示词序列**，把模糊的"帮我建知识库"拆成有状态、有确认门的流程：

- 知识库**四层组成**：本地资料（真实文件）→ README（结构说明）→ AGENTS（操作规则）→ AI 协作（Codex 检查/提方案/执行/自检）；Skills 与总控 Agent 属于成熟阶段，不是首次搭建的必要条件。
- **最小 5 目录**：`00_收集箱 / 01_知识笔记 / 02_原始资料 / 03_归档 / 附件`。
- 完整提示词状态机：只读验证 → 生成最小方案 → 用户提修改意见 → 确认创建 → 3 份资料整理方案 → 确认执行 → 完成一次真实任务 → 结果保存回库。
- 日常四句话：整理新增资料 / 创建项目 / 检查文档更新 / 基于资料输出内容。
- 进阶：项目 `PROGRESS.md`、Skills（重复 3 次以上才做）、总控 Agent（路由组合 Skills）。

### 【曹将】解决"分类该怎么长出来"

曹将（统计学背景）给的是**反完备的知识观**：

- **误区是完备**：不要开局就准备一套标准柜子；每个人情况和处境不同，标准答案不存在。
- **归纳法**：先有再分——建立收件箱，信息都放进去；定期清理，有用的按特点建文件夹；体系在积累中建立。
- **结果是网络**：看到一个词能联想到上下游；深（靠实践，看到细节）+ 广（靠交流、看书听课，看到可能）。
- **落地是简化**：划重点（一页纸指南）、做清单（验收 checklist）。
- **目标是直觉**："当 XX 出现的时候，我就 XX"——持久训练的结果。

### 【潦草】解决"AI 怎么每次都知道该干什么"

潦草学者给的是**上下文工程**：

- Claude Code 本质是 Agent：环境=本地文件；任务=分步推理执行；工具=命令行/文件读写/网络/MCP；记忆=`CLAUDE.md`（长期）+ 对话上下文（短期）。
- `CLAUDE.md` 四段：项目概述 / 常用任务 / 目录结构说明 / 工作流程规范——即"项目说明书 + 工作指南 + 能力边界 + 沟通风格"。
- 七个使用场景：自动日报、智能找文档、批量编辑、一句建数据库、补元属性、帮助思考、开发插件。
- 元数据用 yaml frontmatter；卡片盒笔记法（Zettelkasten）可由 AI 一句指令搭建。
- RAG MCP（文档分段向量化 → 语义搜索）是"第二大脑"的可选增强。

### 三者的分工

曹将回答"为什么不能先设计好一切"（**分类观**）；Blake 回答"每一步人和 AI 各做什么"（**协作流程**）；潦草回答"AI 凭什么记住规则"（**上下文载体**）。三者是同一系统的三个视图，不是三个可选方案。

## 2. 五条底层规律

### 规律 1 · 三层文件治理

| 文件 | 读者 | 内容 | 出处 |
|---|---|---|---|
| `README.md` | 人（+AI） | 库的用途、实际目录、资料流向 | 【Blake】四层组成；【潦草】CLAUDE.md 四段 |
| `AGENTS.md` | AI | 动作许可：直接做 / 先问 / 先备份确认 | 【Blake】AGENTS 六条 |
| `Skills/` | AI | 重复任务的固定步骤 | 【Blake】Skills 章节 |

要点：规则必须**落成文件**，AI 才会在每次新会话读到；只在对话里说的规则会丢。【潦草】的记忆机制给出了依据：长期记忆靠文件，不靠会话。

### 规律 2 · 协作状态机（先方案后执行）

```
只读盘点 → 出方案（带理由）→ 用户审 → 改稿 → 确认 → 执行 → 自检 → 汇报 → 沉淀
```

- 出处：【Blake】全套提示词（每个阶段都明确"现在只输出方案，不操作文件，输出后等待确认"）。
- 三个确认门：方案确认、整理方案确认、执行结果自检。
- AI 负责：检查、提方案、执行已确认动作、自检；用户负责：目标、判断、最终确认。

### 规律 3 · 归纳式分类（反完备开局）

- 开局只设收件箱 + 3–5 个粗目录，不为"完整"创建暂无用途的分类。【Blake】"目录先少后多"；【曹将】"误区是完备"。
- 子目录在资料积累、主题反复出现后再归纳生成。【曹将】"体系在不断积累中建立"。
- 分类必须**读真实内容**再定，不许只看标题猜。【Blake】桶判定要求。

### 规律 4 · 三种产物分层

| 层 | 是什么 | 处置 |
|---|---|---|
| 原始资料层 | 外部来的原文（md/pdf/妙记/媒体） | 只读，不用摘要替换原文 |
| 笔记层 | 基于原文的提炼（一句话/要点/清单/关联） | 新建，挂 sources |
| 卡片层 | 原子化、可跨主题复用的洞察 | 新建，可被多笔记引用 |

- 原文保护：【Blake】"原始资料默认保护正文""不能用摘要替换原文"。
- 卡片层对应【曹将】的"直觉"目标——"当 X 出现时我就 Y"正是一张触发式卡片；"划重点、做清单"是卡片的两种基本形态。

### 规律 5 · 三类结论分开标注

笔记中必须区分：
- **资料原话**：直接引用，带来源；
- **归纳结论**：跨资料合并判断；
- **AI 推断**：资料未明说、模型补充。

出处：【Blake】AGENTS 第 6 条"基于知识库回答时列出参考文件，区分资料内容、归纳结论和 AI 推断"；"资料不足时明确说明缺少什么，不要补写不存在的事实"。

## 3. 规律之间的咬合关系

```
规律3（归纳分类） 决定 目录从哪来
      ↓
规律1（三层文件） 承载 规则与结构
      ↓
规律2（状态机）   约束 每次变更怎么走
      ↓
规律4（产物分层） 保证 原文不被破坏
      ↓
规律5（结论分标） 保证 内容可信可追溯
```

任何一条缺失的后果：
- 缺规律 1 → 规则只活在对话里，新会话失忆（【潦草】所解决的问题）。
- 缺规律 2 → AI 直接动手，用户失去判断权（【Blake】所解决的问题）。
- 缺规律 3 → 开局建一堆空目录，或分类与资料脱节（【曹将】所解决的问题）。
- 缺规律 4 → 原文被摘要覆盖，无法回溯。
- 缺规律 5 → 幻觉与资料混写，知识库不可信。

### 5.2 本 Skill 的归纳/发挥（原文没有直接表述，使用时需知其边界）

| 发挥项 | 依据 | 边界 |

| 源资料留库外只读引用（不进知识库） | 对【Blake】"库内设 02_原始资料"的偏离 | 见 5.3，须向用户说明 |

### 5.3 已声明的偏离：原始资料不进知识库

- 【Blake】方案：原始资料是知识库内的 `02_原始资料`，由 AI 统管入库到归档全周期。
- 本 Skill 默认：源资料目录已作为独立系统存在（自带台账、下载日志、归档脚本），知识库**不复制、不接管**原文，只做只读引用与提炼。
- 这样做的收益：不重复占空间、不与源系统的归档动作冲突、原文始终只有一份。
- 损失：AI 无法在知识库内统一完成资料的归档/重命名；该职责仍归源系统。
- 若用户希望原文进库（Blake 原样），在问卷中显式选择，骨架切换为含"原始资料"目录的形态。
