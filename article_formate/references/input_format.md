# 输入格式规范（草稿写法）

> 本文是**草稿排版模式**的写法。如果你想要的是「给我一篇链接 → 按它的真实样式排我的文章」（HTML 克隆模式），不需要按这个格式写草稿，直接用 `scripts/clone_style.py`（用法见 SKILL.md 的「HTML 克隆排版模式」）。

用户按此规范书写草稿，转换器即可产出统一的公众号排版。语法刻意贴近 Markdown，降低学习成本。

## 1. 标题

```
# 文章大标题（开头主标题 → 品牌红 #d92142，20px 加粗）
## 一级小标题（正文分段主标题 → 品牌红 #d92142，18px 加粗）
### 二级小标题（更细层次 → 深灰 #3e3e3e，16px 加粗）
```

- 最多三级，对应 `themes/<账号名>.json` 的 `headings.h1 / h2 / h3`。
- 标题独占一行，前后留空行。
- **本账号标题统一用品牌红 `#d92142` + 加粗**，靠字号分层级，不用底色/边框（具体外观由 `themes/<账号名>.json` 的 `headings` 控制，用 `-t 账号名` 切换主题即换风格）。

## 2. 正文与段落

- 普通文字即为正文，按 `theme.json` 的 `body` 渲染。
- **空行**用于分隔段落；同一段内换行会被保留为软换行（`<br>`）。
- 行宽建议 35–40 字，便于移动端阅读。

## 3. 行内强调

```
**加粗关键词**（按 theme.emphasis.strong_color 上色，本账号为朱红 #D92142）
*斜体*（轻微强调）
`代码片段`（浅底小字，适合代码/参数）
==高亮重点句==（黄底高亮，按 theme.emphasis.mark_bg / mark_color 渲染，本账号为亮黄底 #FFFB00 + 深色字）
```

> 高亮语法 `==文字==` 为扩展支持：本账号样本大量使用黄底高亮（如关键句），务必用 `==` 包裹。

## 4. 引用

```
> 这是一段引用，可以跨多行。
> 每行以 > 开头即可。
```

按 `theme.json` 的 `quote` 渲染（背景块 + 左边框）。

## 5. 列表

无序列表：

```
- 第一项
- 第二项
```

有序列表：

```
1. 第一步
2. 第二步
```

> 注意：转换器当前**仅支持平铺列表**，缩进的嵌套写法不会生成子列表，请保持列表平铺。

## 6. 分割线

```
---
```

单独一行三个减号，按 `theme.json` 的 `divider` 渲染。

## 7. 图片

```
![图注文字](https://图片地址)
```

- 图注可选；有图注时显示在图片下方（按 `theme.json` 的 `image` 渲染）。
- 图片宽度自适应 `100%`。

## 8. 提示框（可选）

```
::: tip
这里是温馨提示内容，可多行。
::: end
```

支持三种类型：`tip`（提示）、`warning`（注意）、`info`（说明）。以 `::: end` 结束。颜色在 `theme.json` 的 `callout` 中配置。

## 8.5 五步法语义块（intro / section / item / action / ps / footer）

除标题/段落外，五步排版法把文章进一步切成「语义块」，用 `::: 类型 ... ::: end` 围栏语法标注。转换器按设计令牌渲染，无需手写样式：

```
::: intro
Hi！我是XX妈妈，
家有10个多月的小萌娃
职场 + 带娃两手抓
::: end
```
→ 作者/引言区：居中、灰色、多行（`tokens.gray` 驱动）。

```
::: section
一、宝宝10个小动作
::: end
```
→ 一级大板块：黄底（`tokens.highlight_bg`）。

```
::: item
1. 很早就认妈妈
::: end
```
→ 二级分论点：红色加粗（`tokens.primary`）。

```
::: action
我的做法是：把玩具收进柜子，每天只拿出两样。
::: end
```
→ 带 ✅ 的建议句，红色（`tokens.primary`）。

```
::: ps
偶尔去一趟公园，比在家堆叠木更养专注。
::: end
```
→ 备注块：左边框 + 灰底，自动加「ps：」前缀。

```
::: footer
想想妈妈说 · 不制造焦虑，只分享真实育儿干货
::: end
```
→ 底部签名：居中、灰色、上边框。

> 语义块与 `# / ## / ###` 互不冲突：`#` 仍是文章主标题，`::: section/item` 是更细的「板块/分论点」分层。所有颜色/间距都由 `references/themes/<账号名>.json` 的 `tokens` 单一真源驱动。


## 9. 引导关注 / 二维码 / 往期回顾：不用写在草稿里

**这些块由微信平台在发布后自动注入，作者正文里不写、转换器也不生成：**
- 顶部「引导关注」卡片（点开分享链接时显示）
- 底部公众号二维码名片
- 底部「往期回顾 / 相关阅读」卡片

所以你按规范只写**正文**即可，粘贴进编辑器后平台会自动补上这些。

**如果你自己想在正文里带图（例如结尾的「点亮在看」「点个赞」引导图，或自定义二维码）**，就当成普通图片写，转换器按图片规则渲染：
```
![结尾点亮在看，记得点个赞](图片URL)
```
图片整行必须严格是 `![图注](图片URL)`，前后不要有其他字符。

> 注：草稿中不要使用 `{{}}` 占位符——写进草稿会被当普通文字，不读真实内容、也容易误导。

## 10. 完整示例草稿

见同目录 `example_draft.md`，可直接拿来运行测试：

```
python scripts/format_article.py example_draft.md -o demo.html
```

## 11. 注意事项（常见坑，务必避开）

1. **草稿里不要写 HTML 标签**：`<` `>` `&` 会被转义成纯文本显示。要特殊样式就改 `theme.json`，别在草稿里塞标签。
2. **不支持嵌套列表、不支持 ` ``` ` 围栏代码块**：列表只做平铺（缩进不会生成子列表）；三反引号会被当普通段落。
3. **标题 `#` 后必须一个空格**：`#标题`（无空格）不被识别，会成普通段落。
4. **引用 `>` 后必须一个空格**：`>文字`（无空格）不变引用块。
5. **不使用 `{{}}` 占位符**：写进草稿会被当普通文字。引导关注/二维码/往期回顾交给平台，正文要带图用 `![图注](url)`。
6. **加粗/斜体内部别含 `*`**：`**a*b**` 会匹配失败，多余单 `*` 还可能把别处文字误变斜体。
7. **图片整行必须严格是 `![...](...)`**：前后不能有其他字符；URL 一旦含 `)` 会被截断。

## 12. 自定义：修改主题配置（themes/）

所有样式都由 `references/themes/<账号名>.json` 驱动（如当前账号 `themes/xiangxiang.json`）。`references/theme.json` 只是指示默认用哪个账号的分发器，不含样式数值。想微调风格（如标题字号、正文行距、加粗色、高亮色），直接改对应账号文件后重跑转换器即可，无需改脚本：

```jsonc
"headings": {
  "h2": { "font_size": "18px", "color": "#d92142", "font_weight": "bold" }  // 当前账号红标题
},
"emphasis": {
  "strong_color": "#d92142",   // 加粗色（品牌红）
  "mark_bg": "#fffb00",        // 高亮底（亮黄）
  "mark_color": "#1a1a1a"      // 高亮字
}
```

切换账号排版：

```bash
python scripts/format_article.py 草稿.md -t proluo -o out.html   # 用「普罗的小生活」风格
python scripts/format_article.py --list-themes                  # 查看全部账号

## 13. 输出模式：`--emit`（内联 / 标准）

转换器支持两种 HTML 输出，适配不同场景：

```
python scripts/draft_cli.py 草稿.md -o out.html                  # 默认 inline：内联样式，贴公众号
python scripts/draft_cli.py 草稿.md --emit standard -o out.html  # 标准模式：设计令牌 + 语义 class
```

- **inline（默认）**：每个标签挂 `style="..."` 内联样式。微信编辑器会剥掉 `<style>` 与 `class`，只保留内联样式，所以**贴公众号必须用 inline**。
- **standard**：输出带 `:root` 设计令牌与语义 `class` 的标准 HTML（CSS 见 `references/five_step_template.css`）。class 在微信里会失效，仅用于**本地预览 / 自托管 / 归档**。

两种模式共用同一套 `tokens` 与语义词表——改 `tokens` 一处，两模式同时换肤。

## 14. 设计令牌（tokens）：改一处全局变色

样式不再散落各处，而是集中在 `references/themes/<账号名>.json` 的 `tokens` 里：

```jsonc
"tokens": {
  "primary": "#d92142",      // 主品牌色：小标题/对勾/强调/边框
  "accent": "#2e81da",       // 强调色：引用左边框等
  "highlight_bg": "#fffb00", // 高亮/大标题背景
  "text": "#3e3e3e",         // 正文主色
  "gray": "#888888",         // 辅助灰：作者签名/时间/次要
  "max_width": "677px",      // 容器最大宽
  "base_font": "16px",       // 正文基础字号
  "line_height": "2em"       // 行高
}
```

`blocks` 内用 `@primary` 这类引用指向令牌；改 `tokens.primary` 即可让所有红色一次性变。详见 `references/five_step_method.md`。

```
